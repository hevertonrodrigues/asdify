# Open-source positioning and GitHub distribution

## Positioning

**Name:** ASDify  
**One-liner:** Make AI writing easier to understand without dropping the facts.  
**Tagline:** Less fluff. More signal. No lost meaning.

## Differentiator

Most short-answer instructions optimize word count. This skill optimizes **reader effort subject to meaning preservation**. Examples explicitly show what may be removed and what must stay: names, dates, numerical denominators, uncertainty, source citations, and conditional language.

## README structure that helps adoption

1. Concise value proposition and a concrete before/after.
2. One safe install path for each supported agent.
3. Clear explanation of full/lite/ultra modes.
4. Two examples showing why aggressive compression can be wrong.
5. Honest limitations and no false performance figures.
6. Contributing pathway for users to add hard cases.
7. Clear attribution of Ponytail inspiration and ASD-STE100 non-compliance disclaimer.

## Launch plan

**Phase 1: credible v0.1**
- Reserve or confirm the repository owner, name and appropriate license.
- Review README links, installation paths and sample commands against real host versions.
- Run tests and one manual installation for each claimed supported host.
- Record example outputs and compare fidelity, rather than showcasing only shorter answers.

**Phase 2: evidence**
- A/B test English and Portuguese prompts on multiple models.
- Score results blindly, track semantic hard failures, and publish all limitations.
- Add regression fixtures for feedback and mistakes.

**Phase 3: community**
- Publish a short demonstration and reproducible benchmark post.
- Invite examples and counterexamples rather than soliciting artificial stars.
- Submit to relevant Agent Skills directories only where allowed.
- Respond to issues, publish releases and maintain compatibility notes.

## Avoid

- Purchased stars, bot traffic, reciprocal star schemes or other ranking manipulation.
- Fabricated testimonials, comparisons or performance badges.
- Copying another project's logo, personality, marketing text or proprietary benchmark assets.
- Claiming official ASD-STE100 endorsement or certification.

## Suggested core success metrics

- Active usage and successful installs per supported client.
- Meaning-preservation hard-failure rate.
- Blinded pairwise preference and readability ratings.
- First-time contributor rate and bug-report quality.
- Time to resolve reported semantic regressions.
